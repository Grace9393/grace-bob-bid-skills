## Palette Usage for Bid Diagrams

Most bid diagrams need only 4–6 colours. Use this selection as the default:

| Role | Colour | Hex |
|---|---|---|
| Background | White or Gray 10 | `#ffffff` / `#f4f4f4` |
| Body text and labels | Gray 100 | `#161616` |
| Structural lines, borders | Gray 70 | `#525252` |
| Subtle fills, containers | Gray 20 | `#e0e0e0` |
| Primary action / IBM brand | Blue 60 | `#0f62fe` |
| Secondary accent (pick one) | Cyan 60 / Teal 60 / Green 60 | `#0072c3` / `#007d79` / `#198038` |

Reserve Red 60 (`#da1e28`) for risk indicators or warnings only. Use Yellow 30 (`#f1c21b`) and Orange 40 (`#ff832b`) sparingly and never as primary fills on a white background (insufficient contrast for accessibility).

## Prompt Style

Describe visuals as:

- IBM Carbon Design System inspired
- Clean enterprise proposal diagram
- Flat vector, precise grid, strong alignment
- High contrast, accessible, restrained palette
- White (`#ffffff`) or Gray 10 (`#f4f4f4`) background with Gray 100 (`#161616`) text
- Blue 60 (`#0f62fe`) as primary action colour, one secondary accent maximum
- Thin connector lines, simple geometric nodes, minimal iconography
- IBM Plex Sans for body labels and UI text; IBM Plex Mono for code or data values (use Helvetica Neue or Inter as fallback if IBM Plex is unavailable)

Avoid:

- Photorealistic scenes unless the user explicitly asks for photography
- Generic business people, handshakes, cityscapes
- Decorative gradients, glowing effects, bokeh, or floating shapes
- Cartoon style, comic style, 3D render, isometric illustration
- IBM logo usage unless the user confirms brand clearance
- Dense text inside generated images (AI text rendering is unreliable — use blank containers instead)

## Layout Patterns

| Pattern | Description |
| --- | --- |
| Layered operating model | Horizontal bands: governance → service management → delivery → platforms/data → security/assurance |
| Lifecycle loop | Circular or left-to-right phases with feedback arrows: discover → design → transition → operate → improve |
| Swimlane process | Rows per actor (client / IBM / partners / tooling) with handoff arrows and control points |
| Architecture map | Columns or rows: user channels → integration layer → core platforms → data services → security boundary → operations |
| Value chain | Left-to-right flow: client challenge → IBM intervention → service capability → measurable outcome |
| Evidence snapshot | Grid of 3–5 sourced proof points in restrained cards — sourced numbers only, no invented figures |
| Timeline | Horizontal bar with milestone markers and associated metrics |
| Stakeholder model | Node-and-connector diagram showing parties, relationships, and responsibilities |

---

## Text Handling

AI image generators render text unreliably. For diagrams with more than two or three labels:

1. Instruct the prompt to render blank outlined rectangles or containers where text should appear
2. List the exact label text separately in the skill output's "Labels to add manually" field
3. The user overlays labels in Figma, PowerPoint, Canva, or a similar tool

If text must appear in the image, keep each label to 1–3 words maximum and avoid acronyms unless they appear in the source document.
