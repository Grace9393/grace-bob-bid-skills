We’ll implement a pre-existing Defence Data Strategy and Architecture compliant MVP to kick start to HMT. We’ll implement an MVP in 4 weeks and progress to the IOC stage in 8 weeks (in consultation with all partners). The Data System will curate, store, access, and govern HMT Data Holdings.
 
The Data System is cloud-native and architected for scalability, availability, and resilience. We’ll deploy 2 environments: Dev-Test and Production (IaaS Integration) within a single availability zone, running 24/365.
 
The HMT Data System is portable to any cloud (fixed/deployed) by its containerisation and is extensible and scalable as needed. Additional resilience/DR can be provided as needed. 
 
We’ll develop, adapt, and grow the Data System in line with HMT prioritised backlog, IaaS Provider, Users, and lessons learned. It uses open standards, protocols, and open-source components (supported/licensed) throughout the architecture; all can be easily changed depending on HMT’s needs. Its API virtualisation layer delivers access to the HMT Data Structures through RESTful APIs using the OpenAPI/Swagger specification. Foreground IP generated will be owned by the Authority.
 
Our Identity Access Management component controls authentication and authorisation. Role-Based Access Control (RBAC) is applied at several levels e.g. the data product, record, and data item level when accessing data via GUI or API. Authorisation can be further extended through the configuration of additional rules. RBAC is also used to provide access control for all system functions.
 
Version management of changes is vital as data structures and APIs evolve. We’ll design our enhancements to be additive where possible and we will implement a versioning strategy within the OpenAPI specification e.g. version number in the HTTP header or URL.
 
Our Data System also provides a data governance dashboard to enable users e.g. the data governance committee to govern, manage, and analyse their HMT Data Holding
