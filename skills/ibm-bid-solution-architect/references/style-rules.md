# Non-Salesforce Solution Architecture Style Rules

Use these rules for every section.

## Writing Style
- Write for mixed audiences: evaluators, architects, delivery leads.
- Prefer concise statements over long prose.
- Avoid implementation code snippets.
- Focus on architecture intent, constraints, and decisions.

## Required Elements Per Section
- Decision summary (what was selected)
- Rationale (why selected)
- Alternatives considered (at least one)
- Risks and mitigations
- Requirement trace IDs (where applicable)

## Tables and Structure
- Use markdown tables for technology choices, integrations, and risks.
- Use consistent section heading structure.
- Use numbered subsections for repeatable reviews.

## Diagrams
- Describe the diagram content clearly even when image generation is deferred.
- Include the objective of each diagram and key components.

## Context Budget
- Target each section at 400-900 words unless user asks otherwise.
- Do not pull full prior sections into context. Use summary memory only.
