Our DaaS data system has 3 areas where fine-level controls for data access are applied:
• Data ingestion
• Data access control for users
• Data access control via API
Data access ingestion: access controls are configured through the configurable data pipelines. These treat data like code by applying DevOps concepts to data. The DataOps pipeline includes algorithms enabling data manipulation, metadata tagging, and Data Ontology mapping. Data is processed into the data structures, stored, and catalogued. The data access rules will be defined at different levels of granularity e.g. at the data product, record, and data item levels. The Data Owners define the rules to be applied to their data product, and these will be initially configured within the data pipeline by our Data Engineer.
Within the data catalogue, the Data Owner defined rules during ingestion and then dictates the access control to the data: what can be searched, who can see the data, and what level of access they have.
Access to data by users: When a user attempts to access data, the data access rules defined during ingestion will be applied. Access to data will be at multiple levels including at the data product, record, and data item levels as configured in the data pipeline. This capability includes the ability to nest rules allowing a user group permission to see and access some data while obfuscating other data e.g. based on clearance levels or role.
Access to data by API: The same granular access controls will also be applied to data access requests via API. Outgoing data being shared to applications and the IaaS are enabled and controlled via the API layer, which carries across the granular data access rules created in the data pipeline.
By using our rules editor, users with the appropriate role (and permissions), can create new rules or edit or delete existing rules.
All of the above is configured, viewed, and controlled via the intuitive GUI.
