Secure end-to-end message handling
For Semaphore we designed, built, and supported an internet connected message solution to securely handle official sensitive data. We worked with Home Office security accreditors to agree end-to-end security designs, including message encryption and connection protocols.   Different security zones allowed the PNR message ingest from carriers, and MQ forwarded them to more secure zones.  Responses from core traversed the same route backwards, providing responses to the carriers.    Recently we partnered with you to successfully accredit and move the outer zones (APM) to the public cloud.  The new design followed cloud security best-practice, including encryption everywhere, extending ACP services for secure communication channels and integration with IAM, Certificate Manager and KeyCloak services. 
 
Scalability and performance
Over the life of Semaphore, we have worked with you to extend the system with rising passenger movements to process over 1.4billion passenger movements yearly with zero downtime.   Utilising a complex messaging architecture, consisting of multiple clustered queue managers connected using distributed queueing techniques underpinned by MQ, we ensure that every message is guaranteed to be delivered once, and only once, with no data loss.  More recently, APM migrated to AWS, using cloud and container technologies, further enabling elastic scalability, removing hardware dependencies provisioned for peak volumes.  APM is scaled to cope with an average peak of 100 passenger movements per second, averaging 4million passengers daily. 
 
We’re also delivering a new micro-services, message based, core banking capability for a major European Bank. We designed and built cloud-native applications using EKS and AWS services, addressing zero down time and NFRs including security, scalability across multiple zones in this regulated industry. 
 
Resilience and fault tolerance
We designed Semaphore with multiple level resilience:
- Hardware;
- Messaging, through clustered queue managers;
- Applications, using WAS deployment; and
- Operational support.
 
Resilience of our APM design is further achieved using containers and multiple AWS availability-zones.  It's tolerant to poor data, catering for multiple message formats, able to process messages that don’t conform to defined standards providing core processing logic can be completed.
 
For the Schengen-area EU border solution, we delivered a Kafka-based messaging solution, using Kubernetes, with 65 'edge' implementations feeding 3 central clusters.  We used best practices to deliver a highly stable system which meets the 99.999% availability target and zero data-loss objective. The architecture has no single points of failure, using active-active-active distribution of core components and master data stores.  Data is written to three master databases in parallel with only one needing to be available to process transactions.  In the event a site becomes unavailable, transactions continue to be processed, with the failed site processing the transaction log to resynchronise upon recovery.
 
Asynchronous messaging and sequencing
Semaphore employs an asynchronous design pattern using MQ message queues. This caters for large spikes in message volumes and allows different micro-services to be scaled based on demand, enabling Semaphore to continue processing messages while aggregated responses are returned.   MQ manages sequencing, and the workflow logic handles parallel processing based on a message sequence identifier. Our solution also supports high and low priority queues to throttle carrier messages. 
 
We've helped clients, especially in government and financial institutions, to enable the sequencing of messages in the correct order.  For the UK MoD, using APP Connect, we implemented a solution that inserted sequence numbers and processed reordered messages to enable logistic and maintenance transactions to process correctly.
 
Distributed data consumers and integration
Semaphore enables integration carriers, aggregator systems, and data feeds as well as external data services and end users. The system supports 15+ message formats delivered over 6 different connection protocols for ingesting carrier data.   For the APM migration, we successfully managed this complex migration, without business disruption, with 327 carrier cutovers including 489 connections over 20 weeks.
