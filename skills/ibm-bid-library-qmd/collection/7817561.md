Third party reporting systems can be used with the systems involved in the DAM programme and IBM/Cyient have experience using various reporting tools with these products including using Power BI which from our understanding is GT&M’s preferred tool.
Maximo
Maximo is open and easy to integrate with most reporting packages via the powerful integration framework sending information to data warehouses or data lakes, via access to the underlying Maximo database (ODP) or using Maximo’s External Report Integration capability ERI.  In the past, we have used these methods to support Microsoft Power BI, Oracle Reporting Tools, Business Objects and more. You can also integrate Maximo with IBM Cognos using out of the box adaptors. Maximo also has strong internal reporting capabilities through BIRT Reports, Start Centres & KPIs and query driven reports and views.
 

External Report Integration Overview
The External Report Integration (ERI) is available to integrate the Maximo Integration Framework with external reporting systems. These external reporting systems could include a variety of reporting tools, including Hyperion, Information Builders, SAS, Oracle BI or many others. With the ERI, users can access these reports directly from the Maximo applications. For example, a listing of reports can appear and be launched from within the Work Order application. This functionality is very flexible in that it is report system and report version independent.
Open Database Platform (ODP) 
This reporting option enables you to create and view powerful reports based on the Maximo data, which is outside of the Maximo applications and framework. In this method, you configure your reporting tool or tools to connect to the Maximo database; for this method we recommend use of High Availability Disaster Recovery copy of the database so not to impact the performance of the production environment. Your users then view reports created off the database in a separate report portal or viewer. This option again enables you to utilise any reporting tool or version as you simply configure your reporting tool directly to the database.
 
Internal Maximo Reporting
The embedded Maximo reporting tool is Business Intelligence and Reporting (BIRT) which comes with over 100 pre-configured reports. These reports span the variety of the Maximo applications and include drill down, hierarchical, and graphical reports. New reports can also be developed using the BIRT tool as well as enhancing the existing reports if required. 
Sample of BIRT Reports:
Maintenance Cost Rollup 2 Reports are included in this report set.  The first, Maintenance Cost Rollup displays the Work Order Costs the asset incurred since the date the report was last run.   The costs of the assets are rolled up to their parents, and any other levels in the asset hierarchy.  The second, Cost Rollup Update, contains a listing of the data AND updates the Maximo Database with the new values.  By having 2 separate reports, report security can be separated between those that should have View Rights, and those that can update the database.   *Note:  This is a very complex report, therefore, it is highly recommended this report be scheduled or executed at 'off-peak' hoursAsset DetailsDisplays the details of an asset.  Sections included on the report include:  Purchase Details, Downtime, Sub Assemblies, Spare Parts, Meters, Specification, Linear Details, Features and Relationships.  Sections are only included for an Asset if it includes data.  Any costs displayed on this report only reflect the costs that have been rolled up to the asset - they do not include any open costs that have not yet been rolled up through the Asset Cost Rollup Report.Asset Move History For a single asset, displays all its asset move transactions.  The transactions are displayed in descending order of Date Moved to enable the user to focus on the most recent moves first.  This report does not display any non-required parameter values when they are not entered by the user.Asset Purchase Order DetailsThis report displays the POs that the selected assets were created under - grouped by PO.  Since it is grouped by PO, it will show all assets created on the PO even if the asset is not included in the user's query.   
Maximo also has Start Centres that can be used to provide graphical views of information and KPIs within Maximo. These are mainly used by operational Maximo users as a launch point to manage the business processes they are responsible for. Start Centres can be configured for different roles and different data requirements.

 
Finally, Maximo has ‘List Views’ and reports that can be easily filtered and searched using a user-friendly interface or using SQL. The data can also be exported and the queries can be saved for reuse. These list views are available in each application and are generally used to provide a quick real time view of information or drill down into specific areas to undertake root cause analysis.
Esri GIS
Esri GIS Enterprise has a Power BI plugin to utilize mapping data within Power BI.  This can be used to perform spatial analysis of data by creating heatmaps, give context to data by analysing it based on spatial qualities and adding reference data to make better decisions. 
Please use the following link for examples of how geospatial data can be embedded into reports:
ArcGIS Maps for Power BI | Microsoft Power BI
A RDBMS or Cloud native database can be used to store geospatial data within an Enterprise Geodatabase.  In theory, any 3rd party system would be able to query the tables.  
 
Esri GIS is the leading system in its support for OGC and ISO standards. See:
 
https://www.ogc.org/resource/products?display_opt=3&org_match=Esri
 
The server component exposes a RESTful API that may be utilized by 3rd party systems to perform data management workflows or geoprocessing and analytics.
SharePoint Online 
Any reporting tool can consume SharePoint Online data, be it Microsoft’s proprietary product like Power BI, SQL Server Reporting Services or non-Microsoft third-party products like Tableau.
The method of connectivity is either connector (pre-built) for the product or via REST services exposed by SharePoint Online. Power BI uses SharePoint connector, which is already provided by Microsoft, while Tableau uses CData driver with Tableau SharePoint Lists connector.
